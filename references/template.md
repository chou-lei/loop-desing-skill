## 三、自動化測試與交付

**完成條件**（全部通過才算完成）
- `{npm test && npm run build}` 結束碼為 0
- {其他可檢查的條件}

**獨立檢查**
自己的檢查通過後不要直接宣布完成。另開一個只讀不改的子代理，逐項重跑完成條件，回報每項 PASS/FAIL 和證據；任何一項 FAIL 就回到迴圈。
查證關卡：交付物必須經過 cross-verify 交叉查證，並有查證檔（~/research/…）；檢查者要寫明屬於哪一種情況，沒有查證檔就判定 FAIL，回到迴圈。唯一的豁免：交付物不含任何事實陳述、建議或第三方選擇，而且完成條件的指令就能證明正確（純程式碼、設定、格式修改）。

**交付**
- {本機分支 commit，不推送、不部署 | 推到新分支並開 PR，不合併、不部署 | 修改後的檔案 | 只交報告，不改檔}
- 交付前所有完成條件和獨立檢查都必須通過；沒通過就不交付。

**回報格式**
只回報：改了哪些檔案、每項檢查的 PASS/FAIL 和證據、交付物在哪裡、剩下的風險或待決事項。最後一行固定寫：`Evidence: <查證檔路徑>`、`Evidence: exempt — code-only, verified by \`<指令>\``，或 `Evidence: none — BLOCKED (<原因>)`（Stop hook 會檢查這一行）。

## 四、人類設計，AI 執行

- 刪除檔案、資料或分支
- 花錢、購買、付費 API
- 對外發送（Email、訊息、貼文）
- {其他，例如：安裝新套件或工具}

**AI 自主範圍**
在本規格內自行決定做法，不必每一步都問我。

**何時停下來問我**
- 假設不明確，或需求互相矛盾
- 需要擴大範圍，或要動到「不可改動」的項目
- 失敗處理用完仍然沒有通過
- 下一步屬於「需要我批准」的事
